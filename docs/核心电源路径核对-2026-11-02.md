# 核心电源路径核对

## 当前实际行为

- 原生隐藏窗口接收供电变化和自动恢复通知，事件队列满时保留待处理标记。
- 唤醒、队列溢出、设备断线和重新授权会清除规则基线及待执行动作。下一次新读数只重建基线，不立即重放旧模式命令。
- 电源规则使用新读数和设备能力判定；应用结果只有读回确认才报告成功，失败不循环重试。
- 当前接电目标允许安静、平衡、性能和极速；电池目标列表仍为空。因此电池模式自动切换尚未交付，必须等待本机电池条件验证，不能将其称为已完成。
- 当前“唤醒恢复”表示刷新状态并重新建立规则基线，不表示自动重放全部风扇、灯光或性能配置。

依据：`apps/desktop/src-tauri/src/rules_runtime.rs`、`crates/acer-rules/src/lib.rs`、`crates/acer-system/src/power_watch.rs`。

## 本次修复

运行时此前对 `recv_timeout` 使用 `.ok()`，将通道断开与正常超时合并。监听线程退出时，通道立即返回断开，循环可能持续空转并保留过时状态。

现已区分两种错误：超时继续等待；断开时清除规则基线、显示“电源监听已停止，请重启控制台以恢复自动规则”、发送刷新事件并结束循环。

`cargo test --locked -p acer-console -p acer-rules -p acer-system` 通过：5 + 7 + 22 项。此结果支持代码编译和现有规则/系统/退出恢复测试，不包含原生线程异常退出注入或真实睡眠唤醒验收。

此修复晚于 `AcerConsole-Core-Candidate-20261102` 的 14:17 构建。已于 14:23 打入独立目录 `artifacts/AcerConsole-Core-Candidate-20261102-r2`；前端检查、工作区测试及 Release 构建通过。原 14:17 候选包不包含本修复。新包尚未启动进行实机回归。

## 必须补齐的实机验收

用户方便时：拔插电源并记录允许模式，验证规则仅在真实切换时执行；睡眠唤醒后观察新读数、授权连接与基线；检查无旧命令重放。随后按实际结果决定是否需要额外恢复行为。此轮未改变供电、执行睡眠或写入设备。
