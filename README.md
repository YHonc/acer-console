# Acer Console

面向 Acer Predator Helios Neo 16（PHN16-71，BIOS V1.18）的轻量控制台，用 Rust + Tauri 2 + Svelte 5 编写。它的目标是用一个小而透明的程序，承担厂商控制软件里日常要用的部分：硬件监控、性能模式、风扇、键盘灯光、充电保护和外设管理。

> 本项目与 Acer 无关，也不是官方软件。协议来自对本机厂商软件和固件接口的逆向分析，只在上述机型和 BIOS 上测试过。硬件写入会改变风扇、灯光、充电等实际状态，请先阅读[使用与恢复](docs/使用与恢复.md)。

## 设计目的

厂商控制套件常驻多个服务和进程，界面也不区分“设备当前值”和“你刚刚改的设置”。这个项目想解决三件事：

1. **少占资源**：一个桌面进程，加一个只在需要时运行的提权助手；外设功能放进独立模块，用时才启动。
2. **状态可信**：界面把当前值、草稿、设备读回、过期和未知分开显示。读不到就显示“—”，不显示估算值；写入之后以设备读回为准，读回失败会明确标出来。
3. **改动可恢复**：每个硬件写入路径都保存原值，失败或退出时尝试恢复，并记录恢复结果。

## 实现架构

```
apps/desktop          Tauri 2 宿主 + Svelte 5 界面（普通用户权限）
  └─ src-tauri        命令注册、退出协调、Device Center 运行时
crates/
  acer-protocol       协议类型、编解码、原始值解释
  acer-device         串行化的设备访问、温控运行时与恢复
  acer-broker         受限 RPC；acer-helper 是唯一提权组件，只接受白名单方法
  acer-rules          电源规则、温度—风扇曲线计算
  acer-system         Windows 集成：自启动、电源事件、服务插件、模块发现与信任
  acer-controls       辅助设置
tools/probe           探针：默认只读；带 --validate-* 的验证命令会写入并恢复，需显式执行
modules/device-center 外设模块（独立进程，打包时生成，不入库）
```

主要设计决定：

- **权限分离**：界面进程以普通用户运行，需要提权的设备调用经 `acer-broker` 交给 `acer-helper`。助手只暴露固定方法，不接受任意参数。
- **外设走独立进程**：Device Center 是单独的 Tauri 程序，作为文件夹模块随包分发。宿主先核对模块文件的 SHA-256，用户确认信任后才启动它。双方通过当前用户的命名管道通信，握手时校验进程 PID 和随机数，方法有白名单，并分别设置请求超时和读回对账。宿主退出时，给 Device Center 留 5 秒预算，这个预算不影响风扇和温控的恢复。协议见 [DC-IPC 协议 v1](docs/DC-IPC协议-v1.md)。
- **读取不锁界面**：同步设备状态时，控件仍可编辑；写入按资源互斥。草稿和新读回冲突时会提示，不会覆盖草稿。
- **界面基准**：设计令牌和动效集中在 `apps/desktop/src/tokens.css`。动画只由交互或真实数值变化触发，并支持“减少动态效果”。

## 能做到什么

下表分三档：“已实现”指有代码和离线测试；“本机已验证”指在目标机器上做过实际读写和恢复；“待验收”指还缺本机完整回归。

| 功能 | 状态 |
|---|---|
| 温度、风扇转速、供电与电池监控 | 已实现，早期本机读数已核对 |
| 性能模式（安静 / 平衡 / 性能等） | 已实现；探针做过切换与恢复 |
| 风扇 Auto / Max / Custom | 已实现；探针做过 Max 和 Custom 的写入与恢复 |
| 键盘灯光：静态四区与 7 种动态效果 | 已实现；每种效果都做过本机读回与恢复 |
| 健康充电（限充） | 已实现；做过开关读回与恢复，物理截止阈值未测 |
| 软件温控曲线（双曲线、滞回、限频、异常处理） | 已实现，模拟测试通过；本机运行与电源事件恢复待验收 |
| 托盘、自启动、厂商服务插件管理 | 已实现；最新包的管理操作待回归 |
| Device Center 外设页（设备列表、排序、读写、补读对账） | 已实现；两个进程的真实互操作待验收 |
| 精确 CPU/GPU 功耗 | 只有探针：CPU 做过一次 MSR PL1 写入与恢复；GPU 只读桥尚在准备；界面未开放 |

音效仍依赖 Acer Agent / DTS，本项目不提供。

## 验证方式

- `cargo test --workspace --locked`：协议编解码、恢复逻辑、IPC 帧与握手、模块信任等离线测试。
- `apps/desktop`：`npm run check`（svelte-check）与 `npm run build`。
- 界面回归：`design/apple-redesign-20261105/run_checks.sh` 在无界面的 Edge 中逐页检查深浅主题、两种宽度、减少动效、横向溢出和控制台错误，并核对未知值显示为“—”、没有伪造读数。这个检查不需要硬件。
- 本机硬件验收由维护者按[用户功能测试单](docs/用户功能测试单.md)逐项手工完成；构建和离线测试通过不代表硬件已验收。

## 构建

需要 Windows、Rust（MSVC 工具链）、Visual Studio C++ Build Tools、Node.js 和 WebView2 Runtime。

```powershell
cargo test --workspace --locked
cd apps/desktop; npm ci; npm run check; npm run tauri dev
```

发布包用 `scripts/Build-TestPackage.ps1 -Name <名称>` 一次生成，输出控制台、外设模块、文档、清单和 zip。外设模块的源码在独立仓库，需要 GNU 工具链构建，细节见 [模块打包说明](docs/DeviceCenter模块打包说明.md)。

## 开发方式

项目由一名维护者与多个 AI 编码代理协作开发，协作规则也一并入库：

- `AGENTS.md`：所有代理共用的约定，包括状态语义、硬件红线和验证标准。
- `docs/代理协作.md`：模型分工，以及“契约 → 实现 → 本地复验 → 强模型审查 → 合并”的流程。
- `.claude/hooks/guard.py`：命令执行前的安全检查。涉及硬件、电源、引导、磁盘、服务、启动项的命令必须由人确认；删除证据目录直接拒绝。
- `.claude/hooks/session_context.py`：新会话开始时注入当前进度，代理不用翻旧对话就能接手。
- `.claude/skills/`：打包（`test-package`）和界面验证（`ui-verify`）的固定流程。
