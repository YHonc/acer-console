# 自定义模块接口（草案 v0）

日期：2026-11-08。状态：**仅文档，暂不实现**（用户 11-08 决定只保留接口文档）。第 5 节的问题留待真正需要第三方模块时再定；届时升为契约 v1，再委派实现。
基线：`docs/DC-IPC协议-v1.md`（Device Center 模块已按它实现并实测）。本文把其中“宿主 ↔ 模块”的部分泛化，Device Center 成为第一个遵守本接口的模块。

## 0. 为什么用“接口文档 + manifest schema + 参考模块”

| 方案 | 结论 | 原因 |
|---|---|---|
| **独立进程 + 命名管道 + 本文档（采用）** | ✅ | DC 已实测；模块崩溃不拖垮控制台；可按 capabilities 白名单放行；任何语言都能实现（Rust/C#/Python 打包 exe）。 |
| 动态库插件（DLL / `cdylib`） | ❌ | 与宿主同进程，崩溃和内存错误直接影响风扇/温控退出恢复；ABI 绑定 Rust 版本。 |
| 模块自带 HTML/JS 注入界面 | ❌ | 绕过 `tokens.css` 与 `lib/ui` 组件，无法保证“当前值 / 草稿 / 读回 / 过期 / 未知”分开显示；有脚本注入风险。 |
| 只有文档、没有 schema | ❌ | 无法离线校验第三方 manifest，错误要到运行时才暴露。 |

当前交付物是**本文档**（语义与流程）和 **`docs/schemas/module-manifest-v2.schema.json`**（机器可校验）。将来实现时再补一个不碰硬件的参考模块 `modules/example-echo/`，用于离线测试和给第三方照抄。

## 1. 目录与发现

- 位置：`<控制台 exe 目录>/modules/<id>/`，每个子目录一个模块，必须含 `module.json`。
- `id`：`^[a-z][a-z0-9-]{1,31}$`，等于目录名；`acer`、`console`、`system` 保留。
- 发现、哈希校验、信任快照、目录监视（500 ms debounce）沿用 DC-IPC 第 7 节，按 `id` 分别保存快照。首次发现的模块一律 `untrusted`，用户确认后才启动；文件变化后重新进入 `untrusted`。
- 侧栏“服务插件”分节下按模块自动生成入口；模块目录消失时入口折叠隐藏（同现在的 DC 行为）。

## 2. manifest v2（`module.json`）

```jsonc
{
  "schemaVersion": 2,
  "id": "example-echo",
  "name": "示例模块",
  "version": "0.1.0",
  "publisher": "可选，显示用，不代表签名信任",
  "entry": "example-echo.exe",
  "files": [{ "path": "example-echo.exe", "sha256": "<64 hex>" }],
  "protocol": { "major": 1, "minor": 0 },
  "icon": { "glyph": "puzzle", "tone": "indigo" },      // 只能选内置 Icon 名与 .sq 色调
  "permissions": ["hid", "network.lan"],               // 声明用途，界面在信任确认时逐项列出
  "ui": "ui.json"                                      // 可选：声明式界面描述，见第 4 节
}
```

- `schemaVersion: 1`（现有 DC 清单）继续接受，视为 `id=device-center`、界面由宿主内置页面渲染。
- `entry` 只能是模块根内的文件名，禁止参数、脚本、绝对或上级路径；`files` 必须包含 `entry` 与 `ui`。
- `permissions` 取值：`hid`、`network.lan`、`network.internet`、`fs.module`（只限模块目录）、`hardware.write`。**声明 `hardware.write` 的模块，每个写入方法都需用户在信任确认时逐项勾选**（对应 AGENTS.md 的逐项批准要求）。

## 3. 进程与管道

完全沿用 DC-IPC 第 1–3、5、6 节，替换项：

- 启动：`<entry> --headless --pipe <管道名> --parent-pid <宿主 PID> --session <nonce>`。
- 管道名：`\\.\pipe\AcerConsole.<id>.<sidhash>.<nonce>`；互斥体 `Local\AcerConsole.<id>.<sidhash>`。
- `helloAck.moduleId` 必须等于 manifest 的 `id`，否则宿主断开并显示“模块身份不符”。
- 方法名必须以模块自己的命名空间开头（`<id>.` 或在 manifest 中声明的前缀），宿主只放行 `capabilities` 与 manifest 声明的交集。
- 写入方法一律“写后读回”：result 是读回值；不一致返回 `READBACK_MISMATCH`；超时返回 `TIMEOUT`，宿主提示“结果未知，请刷新读回”并补读（DC-IPC 2.2 v1.0.5 的规则原样适用）。
- 退出：`detach` / `shutdown` 与 5 s 预算同 DC；多个模块并行退出，各自 5 s，不影响风扇与温控的退出恢复。

## 4. 声明式界面（`ui.json`，可选）

模块不提供 HTML，只描述“分组 → 行”，宿主用现有组件渲染，保证外观与状态语义一致。

```jsonc
{
  "sections": [{
    "title": "示例设备",
    "read": "example-echo.state.read",            // 返回 { <key>: value|null, stateToken? }
    "apply": "example-echo.state.apply",          // 参数 { change, expectedState }，返回同 read
    "rows": [
      { "key": "power",  "type": "toggle",  "label": "开关", "instant": true },
      { "key": "level",  "type": "slider",  "label": "强度", "min": 0, "max": 100, "step": 1, "unit": "%" },
      { "key": "mode",   "type": "segment", "label": "模式", "options": [{ "value": 1, "label": "安静" }, { "value": 2, "label": "标准" }] },
      { "key": "fw",     "type": "readonly","label": "固件" }
    ]
  }]
}
```

- 行类型只有 `toggle | slider | segment | select | readonly | text`（`text` 需要 `pattern`，可设 `secret: true`，此时值只写不读，读回只给末 4 位）。
- 渲染规则由宿主保证：值为 `null` 显示“—”；草稿与读回分开，草稿只在点“应用”后写入；`instant: true` 的开关点击即写并读回；读回在编辑中变化时显示冲突提示，不覆盖草稿；模块未运行时清空读数。
- 不写 `ui` 的模块只显示状态卡（进程、协议、能力数、保持后台运行开关）。
